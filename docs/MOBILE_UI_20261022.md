# Mobile interface review — 22 October 2026

## Scope and implementation

`frontend/src/mobile.css` is imported after the existing desktop styles. Its rules
apply only at widths up to 1149px, with phone controls and typography at 760px and
below. Scientific calculations, curated inputs and generated contracts are unchanged.

The first built-in-browser check at 390 × 844 found terrain, map and chart cards
collapsed into thin strips by desktop flex/height constraints. Content-sized tablet
and phone panels correct this. A second pass found horizontal overflow from the
distribution legend; disabling column wrapping and bounding the legend corrected it.

Phone controls have larger touch areas. Preset selection spans the toolbar width;
the actions wrap into rows. Terrain/map sidebars follow their canvases, and detail
panels become scrollable sheets with a visible Close action. Charts stack vertically;
ranking rows remain scrollable, the scenario ledger uses two columns, and data
filters fit above the horizontally scrollable records. Sources and Analysis grids
stack without fixed minimum card widths.

Frontend lint, TypeScript, 120 existing tests and production build passed. Backend

## Evidence limits

Viewport resizing does not establish physical-device touch handling, virtual-keyboard
behavior, Safari compatibility, accessibility certification or mobile GPU performance.
Scientific accuracy and historical agreement are outside this layout review. Wide
charts and data tables intentionally retain internal horizontal scrolling for readable
labels and columns.
